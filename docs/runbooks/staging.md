# Staging Environment Runbook

*Created for V2.0 (2026-07-11). Goal: stop testing against the production database.*

> **STATUS: INTENTIONALLY PAUSED (2026-07-18).** Podium-Staging is parked on
> Supabase to free a free-plan active-project slot (WhatMyPetThinks needed it).
> This is deliberate, not an outage. Staging holds zero real data and can be
> restored in a few clicks, or rebuilt from `scripts/staging-replay.sql`.
> **Before rehearsing any new migration, restore it first** (Supabase dashboard →
> Podium-Staging → Restore), then re-pause when done.

## Why

Today there is ONE Supabase project. Vercel previews share the prod DB (only email is
suppressed). Any risky testing — new migrations, seeding flows, vertical templates —
needs a disposable database that looks exactly like prod.

## One-time setup (David, ~10 minutes)

1. supabase.com/dashboard → **New project**
   - Organization: same as prod · Name: `podium-staging` · Plan: **Free** (fine for staging)
   - Region: same as prod (US West) · Save the DB password somewhere safe
2. Open the new project's **SQL Editor**, paste the entire contents of
   `scripts/staging-replay.sql` (all 64 migrations, in order, with banners), Run.
   - If any statement errors, stop and tell Claude the migration number + error text.
3. From **Project Settings → API**, copy: Project URL, `anon` key, `service_role` key.
4. Create `.env.staging.local` in the repo root (git-ignored) with those three values
   using the same variable names as `.env.local`, plus `EMAIL_SAFE_MODE=true`.

## Using staging

- **Local dev against staging:** copy `.env.staging.local` values into `.env.local`
  (or swap files) and `npm run dev`. Swap back when done.
- **Migration rehearsal:** every new migration runs here first; its `-- verify:` queries
  must pass here before David applies it to prod.
- **Seeding/onboarding tests (Phase 7):** create one org per vertical here freely —
  it's disposable. Emails are safe-mode-suppressed regardless.
- Staging has zero real data. To simulate load, create test orgs by hand — do NOT
  copy prod data into staging (musician PII stays in prod).

## Refreshing staging

If staging drifts or breaks: delete the project, redo setup. `staging-replay.sql`
is regenerated by concatenating `supabase/migrations/*.sql` in numeric order — ask
Claude to regenerate after new migrations are added.
